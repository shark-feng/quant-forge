# 框架选型矩阵：AKQuant / PyBroker / Backtrader vs 自研引擎

> 状态：**设计决策文档（M3 交付）**。
> 决策对象：第一阶段/第二阶段的**主回测引擎**由谁承担。
> 结论先行：**主引擎保持自研事件驱动核心**（第一轮已交付 M0~M5）；
> 三个框架分别以「借鉴 / 研究 / 交叉验证」三种**受限角色**接入，任何时刻只有一个主引擎。

---

## 1. 结论摘要（TL;DR）

| 框架 | 定位 | 在本项目中的角色 | 是否进主包依赖 |
|---|---|---|---|
| **自研核心 `aqs.engine`** | 主引擎 | 生产回测、报告、风控 | — |
| AKQuant（akfamily，Rust+Python） | 高性能国产框架 | **设计借鉴**：撮合与事件调度内核思路；不嵌入代码 | ❌ 不进 |
| PyBroker | ML 导向研究框架 | **ML 策略研究平台**：walk-forward、bootstrap 指标 | ❌ 独立 venv / 可选 extra |
| Backtrader | 老牌事件驱动框架 | **交叉验证**：用第二套引擎复核少量策略的净值曲线 | ❌ 独立 venv（GPL 隔离） |

**三条硬边界**：
1. **禁止**三套框架同时当主引擎（合同禁止项）；
2. 主包 `quant-forge` 的**运行依赖不含**任何第三方回测框架，
   框架集成只出现在 `optional-dependencies` 与独立脚本中；
3. 交叉验证/研究的输出**不进入** `reports/` 的正式回测报告，只能写入 `reports/bench/<framework>/`。

### 2.1 AKQuant（akfamily）

| 项 | 内容 |
|---|---|

### 2.2 PyBroker

| 项 | 内容 |

| 项 | 内容 |

### 2.4 自研核心（现状）

第一轮已交付：398 用例全绿、6 类事件、T+1/涨跌停/停牌/整手/参与率撮合、双价格体系、

**这是选型的基线**：任何框架必须显著优于它才值得替换主引擎。

## 3. 选型矩阵

评分：5 = 优秀，3 = 可用，1 = 不具备。（★ 为加权后的关键维度）

| 维度 | 权重 | 自研 `aqs` | AKQuant | PyBroker | Backtrader |
|---|---|---|---|---|---|
| 许可证友好度（MIT/Apache 可商用） | ★★★ | 5（自有，MIT 计划） | 3（**待核实**） | 3（**待核实**，通常 Apache-2.0） | **1**（GPL 系，需隔离） |
| 维护活跃度 | ★★ | 5（本项目） | 4（团队在推文档/教材） | 4 | 2（原版停滞，社区 fork） |
| A 股适配度（复权/ST/整手/分红） | ★★★ | 5（已实现且有测试） | 4（待核实细节） | 4（AKShare 集成） | 2（需自建） |
| T+1 / 涨跌停 / 停牌支持 | ★★★ | 5（有专门回归用例） | 4（待核实） | 3（可扩展） | 2（需自建） |
| 事件驱动能力 | ★★ | 5（6 类事件 + 步骤优先级 + 录制器） | 4 | 3（逐 bar 为主） | 5 |
| Tick / 订单簿支持 | ★（第三阶段） | 2（待建） | 3（待核实） | 1 | 2 |
| ML 集成（特征/滚动训练/自助法） | ★★（第二阶段） | 3（自建，M9 起） | 4 | **5** | 2 |
| 性能 | ★★ | 3（纯 Python，519 交易日 < 10s 可接受） | **5**（Rust 核心） | 4（Numba） | 2 |
| 可测试性（能否逐条断言内部行为） | ★★★ | **5**（398 用例、可断言事件顺序/撮合细节） | 2（黑盒） | 2 | 3 |
| 与自研边界清晰度（可隔离、可移除） | ★★ | 5 | 3 | 4 | 2 |
| **加权合计** | — | **加权最高** | 次之 | 次之 | 最低 |

### 3.1 为什么结论是「保持自研」（而不是换框架）

1. **合同约束优先**：第一轮已按合同把 T+1、涨跌停、停牌顺延、成本模型、PIT 写成**可断言的测试**；
   换成框架后这些验收点全部变成「对第三方黑盒行为的信任」，等于放弃验收能力。
2. **可测试性差距最大**：我们的关键验收（事件顺序、订单生命周期、撮合判定顺序、
   `LookaheadError`）都要求能**读到内部状态**；框架化会把这些封进黑盒。
3. **数据层是本项目的真正差异点**（PIT + 双价格 + 公告日 + 幸存者偏差），
   任何框架都不提供，换成框架等于换汤不换药，却要付出迁移成本。
4. **GPL 风险**：Backtrader 作主引擎会污染整个仓库的许可策略；作为隔离的交叉验证工具则可控。
5. **迁移成本**：主引擎替换需重做 M2/M3/M4/M5 的全部回归用例（≈300 条），收益不明确。

### 3.2 什么情况下会重新评估

- 数据量级提升到「全 A 股 × 分钟/Tick」导致纯 Python 成为瓶颈（→ 优先做**向量化加速**或
  引入 Rust 加速插件，而非换框架）；
- 需要实盘通道（本阶段明确不做）；
- 第二阶段因子研究的**组合优化**部分需要成熟 solver（→ 用 cvxpy，仍不涉及框架选型）。

## 4. 集成方案与边界

```
                      ┌──────────────────────────────────────────────┐
                      │  主链路（唯一主引擎）                          │
   数据层 DataProvider →│  aqs.engine + aqs.strategy/portfolio/risk    │→ 报告
                      │  aqs.metrics / aqs.report                    │
                      └────────────────────┬─────────────────────────┘
                                           │ 只读：净值曲线 / 成交明细（CSV）
        ┌──────────────────────────────────┼──────────────────────────────────┐
        ▼                                  ▼                                  ▼
 ┌───────────────┐                 ┌───────────────┐                 ┌────────────────┐
 │ 交叉验证脚本   │                 │ ML 研究脚本    │                 │ 设计借鉴（无代码）│
 │ tools/bench_  │                 │ tools/ml_     │                 │ docs/12 比对笔记 │
 │ backtrader.py │                 │ pybroker.py   │                 │ → 只影响自研实现  │
 │ (独立 venv)    │                 │ (独立 venv)    │                 └────────────────┘
 └───────────────┘                 └───────────────┘
```

| 角色 | 输入 | 输出 | 隔离方式 | 验收 |
|---|---|---|---|---|
| 交叉验证（Backtrader） | 我们导出的 `bars.csv` + 交易清单 | `reports/bench/backtrader/*.csv` | **独立 venv**，不写入 `pyproject` 依赖；GPL 代码不进入主包 | 两引擎在同一策略上的净值相关系数 > 0.98（差异可解释：成本/整手/顺延口径） |
| ML 研究（PyBroker） | AKShare 数据（同一 provider） | 研究报告（不进正式报告） | `optional-dependencies.ml`，独立 venv | walk-forward 结果可复现（同 seed） |
| 借鉴（AKQuant） | 其文档与源码阅读 | `docs/12` 附录：可借鉴点清单 | 无代码依赖 | 至少产出 3 条可落地的改进项（如撮合内核、成本模型接口） |

**边界纪律（写进 `docs/DEVELOPMENT.md`）**：
1. 框架脚本只能**读**导出文件，不得 import `aqs.engine` 内部状态；
2. 框架输出目录固定 `reports/bench/<framework>/`，在 `.gitignore` 中；
3. 任何「框架里跑得更快/更准」的结论都必须**回到自研引擎可复现**才允许写进正式报告。

## 5. 许可证风险评估

| 框架 | 许可证（待核实） | 若作为主引擎 | 若作为隔离工具 | 处置 |
|---|---|---|---|---|
| AKQuant | 未核实 | 需接受其条款并承担传染风险 | 仅阅读（无代码引入） | 只借鉴设计 |
| PyBroker | 通常 Apache-2.0（待核实） | 可商用，但架构不匹配 | 可用于研究脚本 | 可选 extra，独立 venv |
| Backtrader | **GPL 系**（社区广泛讨论） | **禁止**（传染主包） | 独立进程 + 独立 venv + 不链接 | 仅离线交叉验证 |
| AKShare | MIT（待核实） | 依赖使用 | — | `NOTICE` 署名 |

**处置结论**：
- 主包 `quant-forge` 采用 **MIT**；
- `NOTICE` 中列明：AKShare（数据来源与署名）、pandas/numpy/scipy/statsmodels/cvxpy 等第三方库、
  以及「本项目未包含任何 GPL 代码；交叉验证脚本独立运行且不随主包分发」的声明；
- 若未来确需集成 GPL 组件：必须放到独立仓库/独立脚本，并在 `NOTICE` 中显式声明。

## 6. 决策记录（ADR）

```
ADR-0001 主回测引擎选型
状态：已决定（第二轮 M3）
背景：第一轮已交付自研事件驱动引擎（M0~M5，398 用例）；需决定是否迁移到 AKQuant/PyBroker/Backtrader。
决策：保持自研引擎为主引擎；三框架以「借鉴 / 研究 / 交叉验证」受限角色接入。
理由：(1) 合同验收点要求可断言内部行为；(2) 数据层为本项目差异点，框架不提供；
      (3) GPL 风险；(4) 迁移成本 ≈300 条回归用例；(5) 性能瓶颈可用向量化/Rust 插件解决。
后果：需自建因子/优化/波动率模块（已在第二阶段设计中规划）；
      交叉验证成本增加（需维护独立 venv），但换来可测试性与许可清晰。
替代方案：若第二阶段需要大规模 ML 流水线，则以 PyBroker 做研究、结果回灌自研引擎复现。
```
